# Visual design

## The brief

One large Japanese word with furigana over its kanji, an English gloss
beneath, a Japanese example sentence beneath that, and the standard title bar
at the bottom. Sparse on purpose: no cards, boxes, borders, gradients,
progress bars, illustrations or incidental metadata.

The baseline is the original 800 × 480 panel.

## Hierarchy

1. **Target word** — dominant, always one line, furigana over the kanji only.
2. **English gloss** — one concise phrase, normally one line.
3. **Japanese example** — one or two lines in the full view.
4. **English translation** — optional, off by default, visually secondary.
5. **Title bar** — `Japanese` on the left, the level as the instance on the right.

## Furigana rules

- Ruby sits over kanji-bearing runs only. Okurigana stays plain beside it:
  取り除く is と over 取 and のぞ over 除, with nothing over り or く.
- Contiguous kanji whose reading cannot be split per character stay as one
  group: 学校 / がっこう, 今日 / きょう.
- A kana-only word produces no `<ruby>` element at all, and never an empty
  `<rt>`.
- Ruby text is 28% of the base size — inside the 24–30% the brief allows,
  legible on e-ink, clearly subordinate.
- The gap between a reading and its kanji is reserved by the browser's ruby
  layout. Neither `transform` nor `line-height` on an `rt` box will move it;
  attempting either produces CSS that looks meaningful and does nothing.
- Japanese containers carry `lang="ja"` so the renderer prefers Japanese glyph
  variants.

The markup is generated by iterating precomputed segments, never inferred:

```liquid
{%- for segment in segments -%}
  {%- if segment.reading and segment.reading != blank -%}
    <ruby><rb>{{ segment.base | escape }}</rb><rt>{{ segment.reading | escape }}</rt></ruby>
  {%- else -%}
    {{- segment.base | escape -}}
  {%- endif -%}
{%- endfor -%}
```

The whitespace control matters: without it, Liquid's newlines become spaces
inside the word.

## Type scale

Sizes are custom properties set on the view container. Each element resolves
its own with a single rule.

Every number below is a multiple of `--kotoba-unit`, which is
`calc(var(--screen-w, 800px) / 800)` — one unit equals 1px on an 800-wide
panel. The Framework sets `--screen-w` per device (800px for `screen--og`,
1040px for `screen--v2`, which is what a TRMNL X reports), so the whole card
scales with the hardware instead of being pinned to the original panel. The
table therefore reads in *baseline* pixels; on a 1040-wide screen everything
is 1.3x larger. The `800px` fallback means a preview with a bare `.screen`
renders exactly the tuned baseline.

| | short | medium | long | xlong | gloss | example | translation |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Full 800×480 | 108 | 92 | 74 | 56 | 32 | 25 / 22 / 19 | 18 |
| Half horizontal 800×240 | 62 | 54 | 46 | 38 | 23 | 18 / 17 / 16 | — |
| Half vertical 400×480 | 52 | 46 | 38 | 30 | 21 | 17 / 16 / 15 | — |
| Quadrant 400×240 | 40 | 34 | 28 | 24 | 18 | — | — |

Example sizes are normal / compact / tiny.

Width classes come from the payload, computed at build time from an estimated
display width in full-width units: `short` ≤ 3, `medium` ≤ 5, `long` ≤ 7.5,
`xlong` beyond that. The widest word in the corpus is
デモンストレーション at 10 units, which fits every layout at its `xlong` size.

### Why custom properties rather than one rule per size

`trmnlp lint` caps the total number of declarations of a small set of
properties — `font-size`, `margin`, `padding`, `text-align`,
`justify-content` and a few others — at six across all markup. Writing
`font-size` once per size class per view would be about thirty. Custom
properties keep the same design inside the budget, and they happen to be
easier to read too. Spacing uses flex `row-gap` for the same reason, and greys
use the Framework's `text--gray-*` classes because `opacity` is disallowed.

If you add CSS, run `make lint-plugin` before pushing.

## Per-layout behaviour

**Full** — word, gloss, Japanese example (up to two lines), optional English
translation, title bar.

**Half horizontal** — word, gloss, example clamped to one line. The English
translation is suppressed regardless of the setting.

**Half vertical** — word, gloss, and the example only when it fits cleanly.
It is dropped when `example_size` is `tiny` or the word is `xlong`, on the
grounds that a cramped sentence is worse than none.

**Quadrant** — word and gloss only. There is no honest way to add a sentence
without shrinking the word below the point of being the dominant element.

The word never wraps in any layout.

## Acceptance checklist

Render with `make render-fixtures` and check `dist/renders/`.

For `full_reference` (取り除く / eliminate):

- [ ] と sits above 取
- [ ] のぞ sits above 除
- [ ] り and く have no furigana
- [ ] the word is one centred line
- [ ] the ruby does not touch the top of the frame
- [ ] `eliminate` is centred beneath the word
- [ ] the Japanese sentence is centred and legible
- [ ] the title bar is at the bottom and overlaps nothing

Across the rest of the fixtures:

- [ ] `kana_only` shows ありがとう with no ruby and no empty annotation
- [ ] `irregular_reading` shows きょう over 今日 as one group
- [ ] `wide_ruby` shows うけたまわ spread over 承, spacing out the base
- [ ] `xlong_word` fits デモンストレーション on one line in all four layouts
- [ ] `with_translation` shows the English line, greyed and secondary
- [ ] `with_progress` shows `N3 · 221/1730` in the title bar
- [ ] `empty_state` shows "Vocabulary unavailable" with the level and date,
      and keeps the title bar
- [ ] every `level_n*` fixture shows the right label
- [ ] nothing overlaps the title bar or the frame at 800 × 480

Pixel-perfect golden-image comparison is deliberately **not** a gate: CJK font
fallback varies between environments and would produce false failures. CI
gates on a successful render producing non-empty output for every view of
every fixture, and uploads the PNGs as artefacts. Changes to Liquid or CSS
need a human to look at them.

## Checking the larger panel

`trmnlp` previews at 800x480 and emits a bare `.screen`, so to see what a
TRMNL X gets, force both dimensions and render at that size:

```sh
printf '\n<style>.screen{--screen-w:1040px;--screen-h:780px;}</style>\n' >> src/shared.liquid
bin/trmnlp build --png --width 1040 --height 780
git checkout src/shared.liquid    # undo the override
```

Override *both* variables. Setting only the width grows the type while the
layout box stays 480 tall, and the card overflows — which is a bug in the
test, not in the design.

## Rendering PNGs locally

The official `trmnl/trmnlp` image ships no CJK fonts, so Japanese renders as
tofu boxes. `Dockerfile.trmnlp` adds Noto Sans CJK; `make trmnlp-image` builds
it and the render script uses it by default. No font is bundled into the
plugin itself — the device uses the renderer's own fonts.
